legacy: remove the dropped item after the pickup animation

When the backend announces a pickup (TakeItemEntityPacket) the bridge sent only the 0.14
TakeItemEntity, which just plays the animation, and it also dropped the item from its own
mapping while doing so. The backend's own RemoveEntityPacket then arrived, found no mapping
left and was filed as "removed before shown" instead of being forwarded — so the drop stayed
on the ground for good.

The 0.14.3 reference does exactly what is now done here: broadcast TakeItemEntity and then
entity.kill(), which despawns the drop with a RemoveEntity. The wire order of the pickup
packet itself ([target=item][entityId=collector]) was already correct.
